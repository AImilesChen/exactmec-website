# Optional analytics choice panel

The widget is client-only and rendered only when the parent enables optional measurement. It uses the shared `MEASUREMENT_CHOICE_KEY` v3 and `readSavedMeasurementChoice`; earlier first-party-only or three-provider permissions do not grant permission for the added Ahrefs provider. Startup denial is sent to the wrapped controller; SDK teardown/reload is owned by that controller.

The default notice briefly explains optional cookies and masked marketing-page recordings, without affecting inquiries. A native **Services & privacy details** disclosure names Google Analytics 4, Microsoft Clarity session recordings/heatmaps, ShipSolo-hosted Plausible analytics and Ahrefs Web Analytics and explains cookies, device/IP/network processing and excluded forms/accounts/admin. It is available before choosing. Privacy and cookie policies remain visible. Two equal-sized actions display **Reject** and **Allow**, with the full accessible names **Reject optional tracking** and **Allow analytics and recordings**. The persistent **Measurement choices** button reopens the same panel, and rejection is also withdrawal.

The panel is a nonmodal white/light-blue-gray card in the bottom-right corner, away from the homepage title and CTA, with a restrained red allow button. Its width is capped at 420px, with 16px viewport insets, 20px padding, an 18px heading and readable 14px main copy. Two 44px-high controls share one row, including on mobile. Expanded details scroll within the visible height. It never traps focus or blocks the ordinary inquiry flow. Panel and controls are masked for Clarity. Existing page typography and layout remain untouched.

Selection saves the shared preference before invoking `analytics.setConsent`. The parent wrapper then handles third-party permission and, on withdrawal after SDK startup, removes optional cookies and reloads with the refusal marker. A storage failure is described as page-only permission, not a saved permanent preference. Synchronization listens to the versioned storage key. A new permission emits at most one explicit pageview for a known public marketing route, never an RFQ/private/legal/system route. The UI does not install SDKs or decide vendor hostname permissions itself.

`tests/analytics-measurement-choices.test.mjs` exercises write-before-controller ordering, allow-pageview scope, storage-failure wording, provider/exclusion disclosures, client-only rendering and balanced action labels. Actual browser vendor networking, consent revocation cleanup and masks require the parent integration checks.
