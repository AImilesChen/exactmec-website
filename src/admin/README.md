# Authenticated inquiry management

Independent entry: `admin.html` → `src/admin/entry.jsx`. The public app imports none of this directory. The parent build/router must map protected `/admin/leads/` to this HTML, include the separate entry in its multi-page build, and protect both HTML and APIs using verified production Access identity. UI presence is not authentication. All authenticated responses need `Cache-Control: no-store` and `X-Robots-Tag: noindex` from the server. The entry intentionally has no third-party analytics or scripts.

The client follows `../../backend/CONTRACT.md`: session, POST search, detail, optimistic PATCH, channel opt-out, internal-notification retry, POST CSV export and revision-confirmed DELETE. It holds the CSRF token only in a closure. Every non-GET admin API call sends `X-CSRF-Token`; all requests use same-origin credentials, no-store, no-referrer, blocked redirects and a 15-second timeout covering parsing. It never retries mutations automatically. There are no records, credentials, queries or customer fields in application URLs, browser storage or console output. The opaque reference appears only where required by the protected API contract. Error UI uses fixed messages, never raw server/customer error text. Search is bounded to 120 characters, pages to 10,000, page size to 100, and drawing filters to the contract's exact options.

The Chinese UI provides search/filters/pagination, authenticated raw project details, contact reveal, independent consent records, review/qualification/priority/owner/follow-up date, notes and history, notification state/retry, opt-out, CSV confirmation and destructive deletion confirmation. API errors show an explicit failure; no demo records or fake success are created. A 409 or uncertain mutation locks further edits/contact until explicit detail reload. Authentication failure clears loaded records. CSRF failure requests explicit session refresh and never silently replays a write.

Contact display starts collapsed. No `mailto`/WhatsApp customer URL is present in rendered links. Opening an external contact application requires revealing details and clicking the relevant button. Server `contact.whatsapp_allowed` / `email_allowed` must be the boolean true; contact permission is never inferred from the presence of a number or from the original consent receipt. `contact.stopped` indicates some channel is suppressed, so an explicitly allowed email reply remains possible after WhatsApp-only suppression. The UI cannot override server suppression. WhatsApp drafts contain only a generic follow-up sentence and the opaque reference; no project/name/budget enters a draft. Opening an app does not send a message. Telephone/call actions are deliberately absent.

CSV export is downloaded from the authenticated response Blob after a confirmation, using a fixed generic filename and a short-lived object URL that is revoked. Formula escaping/BOM/row bounds must be guaranteed by the server. Delete requires typing the exact reference and the current optimistic revision; the UI explains that minimum contact-suppression records remain. There is no automatic deletion schedule or invented retention duration.

Integration expectations: payload uses `src/inquiry/model.mjs` snake_case, including `budget_min`, `budget_max`, `currency`, `purchase_timing`; `consents` and history shapes are defined in the backend contract. Notification shape is `{reference,state,attempts,errorCode?}`, where state is pending/sending/sent/failed/disabled. `403` JSON should include a fixed error code containing `csrf` for expired CSRF; generic 403 is treated as permission denial. Live or synthetic notification retries do not contact customers; they request the configured internal-notification pipeline only. Unknown notification states are shown as unconfirmed.

Verification: `node --test tests/admin-client*.test.mjs`. Tests use mock fetch and synthetic data only. Parent owns the full build and localhost API/browser integration at `http://127.0.0.1:4176/admin/leads/`. Production Access, approved collection, notification secrets and legal publication remain separate configuration gates.

## Content drafts

The authenticated app now has separate “询价管理 / 内容草稿” navigation. `ContentWorkspace.jsx` reads the real `/api/admin/content` API rather than the historical Operations mock. Page selection, metadata fields, collapsible section heading/paragraph/bullet forms and collapsible FAQ editing use API-provided baseline and saved patch. Paragraphs use blank-line separation; bullets use one line per item. `content-model.mjs` constructs the closed editable patch and excludes card/table/CTA/image/path/order fields. No raw JSON editing is used. The UI explains that these fixed layout elements require the separate layout review.

`listContent`, `getContent`, `saveContent`, `exportContent` share the same authenticated client and in-memory CSRF token. Save includes optimistic revision (initially 0) and current 64-character source hash; content writes are limited to 64 KiB and contract text bounds. Source and revision conflicts have distinct fixed errors, never automatically retried. Any conflict or uncertain write locks the editor until explicit reload. If a persisted draft is based on old source, the UI exposes current source comparisons and requires an explicit review choice before saving a new patch against the current hash. Removed source sections are omitted from this reviewed replacement. Stale drafts and locally unsaved changes cannot be exported.

Save confirmation is “草稿已保存，未发布”. Export requires a modal confirmation, posts only the source hash, and downloads the JSON response Blob using a safe page-ID filename with a revoked object URL. It does not wait on browser download events, edit public content, publish, commit, push or deploy. Source compatibility and export authorization remain server enforced. API failure does not substitute locally imported site content; the real baseline imported in the test is used only to verify form compatibility.

Additional verification (kept inside the assigned `src/admin/` ownership boundary): `node --test src/admin/content-client.test.mjs`. It covers CSRF/revision zero, the editable schema and text bounds, fixed-field exclusion, all 24 baseline forms, distinct conflicts, stale/rebased export, and explicit API failure without fallback. Existing lead client tests remain unchanged and must continue passing.
