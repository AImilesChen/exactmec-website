The owner authorized the guest inquiry form, formal legal pages, protected staff dashboard, sales notification and optional WhatsApp continuation. This collects a request for a later human quotation; it does not calculate a price, take payment or send a WhatsApp message. The form can accept drawings into private R2 storage. Budget and purchase timing are optional.

Build with `npm run build:release` and use the matching formal notice values in `src/data/notice-versions.json`. Enable the independently required collection/legal/backend/contact flags. The owner requested organic Google discovery on 2026-10-27: set both `VITE_SEO_INDEXING_ENABLED=true` at build time and `SEO_INDEXING_ENABLED=true` on the Worker for the same release. Confirm the generated marketing routes, canonical tags, robots directives and sitemap before deploying. Legal, system, account and admin paths remain excluded from indexing; enabling the inquiry form alone never enables indexing. Keep customer email authentication disabled for this release. Optional external analytics still require the visitor's choice and remain excluded from inquiry, account and admin pages.

Cloudflare Access protects `/admin` and `/api/admin` with one audience and an explicit private administrator allowlist. Temporary prelaunch protections on `/request-a-quote` and `/api/inquiries` must be removed for guest submissions. The owner deferred personal login testing and the second administrator's authentication setup; do not add an IdP, change the existing mailbox login or invite an account member to force that test. The public sales address is only a contact and notification address, never an administrator.

Deployment uses the existing EXACTMEC Worker and D1, preserving independent Worker secrets and the restricted sales-to-sales email binding. Run the full frontend/backend checks before deployment and verify a single clearly marked synthetic inquiry after deployment. Record D1 persistence and notification delivery separately from personal dashboard login. Check anonymous admin denial, guest access, exact notice versions, idempotency and the generated WhatsApp reference URL. Never treat a native mail acceptance or an outbox `sent` state alone as recipient delivery.

The following defaults describe unconfigured candidates and historical review deployments; they are not evidence that the approved live form is still disabled.

`worker.mjs` is separate from the protected prototype Sites worker. It serves allowlisted static assets and routes `/api/**` to the backend. Without the intended database, approved collection configuration and strong secrets, inquiry writes fail closed. Admin APIs independently require verified Access identity, an explicit allowlist and CSRF for writes. Other public write methods return 405. See `../backend/README.md` and `../backend/CONTRACT.md`.

Bind static files as `ASSETS`. Set `RELEASE = "false"` and `LEGAL_APPROVED = "false"` by default. Staging can display legal drafts for review, always with `X-Robots-Tag: noindex,nofollow` and `Cache-Control: no-store`. Release mode blocks legal routes unless the independent legal approval flag is true. It does not replace build-time publication checks.

The static build must emit `/index.html`, route-specific `/about/index.html` etc., legal `/privacy/index.html` etc., and `/404.html` (alternative `/404/index.html` also supported). External legal paths remain slashless. Configure ASSETS `html_handling: "none"`, `not_found_handling: "none"`, and run the Worker before assets; this adapter owns canonical redirects and 404 behavior. Do not configure a host SPA fallback. Deployment and public release require separate authorization.

Only named root runtime assets and image/font/CSS/JS files inside `/assets/` or `/brand/` are public. Design previews, workbench routes, source, sourcemaps, downloads and ZIP archives are rejected even if mistakenly copied. The admin HTML is served only through authenticated `/admin/leads/`; requesting its raw asset path does not bypass the check. Missing HTML assets return true 404; aliases and prepared-industry fallbacks return explicit 308. Runtime HTML/scripts/fonts stay same-origin under the security headers; no analytics/chat SDK is enabled. Inline styles are permitted for the existing React/CSS implementation.

`wrangler.jsonc` is the default data-disabled candidate. `wrangler.staging.jsonc` binds the independent EXACTMEC review database but disables workers.dev, preview URLs, routes, collection and notifications. `wrangler.backend.example.jsonc` is a template for future approved operation. No config file alone proves a deployment, Access policy or mail service exists. A static confirmation page retains its no-submission fallback until a server-confirmed save exists.
